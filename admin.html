🔎 Je veux…

    📌 Le principe en 1 minute

    • Le contenu de chaque jeu (questions, mots, chansons, logos…) est dans des fichiers du dossier data/, et parfois des images ou vidéos dans public/. Il n'y a pas de base de données.
    • Chaque jeu a un script de vérification qui relit son fichier et signale les erreurs. On le lance après chaque modification.
    • Le jeu en ligne tourne sur Render, qui prend automatiquement la branche main de GitHub. Donc : une modification n'est visible en soirée qu'une fois poussée sur main.

    La routine, pour n'importe quel ajout

    1. Récupérer la dernière version : git pull.
    2. Modifier le fichier (ou lancer l'outil du jeu). Voir la fiche du jeu.
    3. Lancer le script de vérification du jeu, puis npm test.
    4. Essayer en local (Tester en local).
    5. Enregistrer et envoyer : git add, git commit, git push (Mettre en ligne).

    Jamais de push sur main pendant une soirée : Render redémarre le serveur et toutes les parties en cours sont perdues.

    Tu peux aussi demander à Claude dans ce projet, par exemple : « Ajoute 20 questions au quiz en sport, niveau 2, en suivant admin.html ». Relis toujours ce qu'il propose avant de pousser.

    ✏️ Modifier un fichier de contenu (JSON)

    Les fichiers data/*.json sont des listes : [ au début, ] à la fin, et entre les deux des blocs { … } séparés par des virgules. Un bloc = une question, une paire, une chanson…

    Ajouter un élément

    1. Ouvre le fichier dans ton éditeur et va tout en bas.
    2. Copie le dernier bloc { … } et colle-le juste après, en mettant une virgule entre les deux.
    3. Change l'id : prends le numéro suivant (après q0300 vient q0301). Garde le même nombre de chiffres.
    4. Remplace le reste par ton contenu, en gardant les guillemets droits ".

    Corriger ou retirer un élément

    • Retrouve-le avec Ctrl+F sur un mot de son texte.
    • Pour corriger : change le texte, garde l'id.
    • Pour retirer : efface tout le bloc, et la virgule qui devient en trop. Ne réutilise jamais cet id.

    Les pièges classiques

    • Une virgule oubliée entre deux blocs, ou une virgule en trop après le dernier bloc : le fichier devient illisible. Le script de vérification le signale.
    • Des guillemets « typographiques » ou ” à la place de " autour des valeurs. À l'intérieur d'un texte, « … » et l'apostrophe ’ sont permis.
    • Pas besoin de variantes pour les majuscules, les accents, les articles ou les pluriels en s/x : le jeu les ignore déjà en comparant.
    • Préfixes d'id réservés : q quiz, e estimation, n qui de nous, u undercover, m même réponse, b bluff, g légende, d blind test, l géoquiz, n-… nuancier.

    🖥️ Tester en local (sur ton ordinateur)

    1. Ouvre PowerShell dans le dossier du projet (ligne cd en haut de la page).
    2. Lance le serveur en mode développeur (une partie à 1 joueur est alors permise dans tous les jeux) :

      Le serveur redémarre tout seul quand un fichier du serveur change. Pour un fichier data/, s'il ne redémarre pas, arrête-le et relance-le. Pour l'arrêter : Ctrl+C dans PowerShell.

    3. Ouvre la TV dans Chrome : http://localhost:3000/tv (fenêtre en plein écran, touche F11, pour voir comme sur la TV).
    4. Ouvre un ou plusieurs joueurs : http://localhost:3000/joueur?dev. Avec ?dev, chaque onglet est un joueur différent. Tape le code affiché sur la TV et un pseudo.
    5. Le premier joueur est l'hôte : il choisit le jeu, les options et lance la partie.

    Sur le PC du travail, le pare-feu empêche les téléphones de rejoindre le serveur local : joue avec des onglets /joueur?dev. Le vrai test avec téléphones se fait sur Render.

    📖 Lexique

    PowerShellLa fenêtre où l'on tape les commandes (menu Démarrer › PowerShell). On colle avec clic droit ou Ctrl+V, on lance avec Entrée.
    JSONLe format des fichiers de contenu : du texte structuré avec [ ], { }, des guillemets et des virgules.
    idL'identifiant unique d'un élément (q0042). Le jeu s'en sert pour ne pas reposer deux fois la même question dans une soirée.
    GitL'outil qui garde l'historique de toutes les versions du projet.
    commitUn enregistrement, avec une phrase qui décrit le changement. Il reste sur ton ordinateur tant qu'il n'est pas poussé.
    pushEnvoyer ses commits sur GitHub. pull : récupérer ceux des autres.
    brancheUne version parallèle du projet. main est la branche officielle, celle que Render met en ligne.
    pull requestSur GitHub, la demande de fusionner une branche dans main. « Merge » la fusionne.
    RenderL'hébergeur du jeu en ligne. Il redéploie à chaque push sur main.
    local / localhostLe serveur qui tourne sur ton ordinateur, à l'adresse http://localhost:3000. Personne d'autre ne le voit.
    hôteLe premier joueur entré dans la salle : il choisit le jeu et lance la partie.
